Different algorithms do different jobs. Some predict numbers, some choose between categories, and some find groups. Machine learning uses examples to produce answers, so the first step is to decide what kind of answer you need: a number, a category, or a group. The picture beside this paragraph shows the basic idea: start with examples, decide what sort of answer you want, use an algorithm to produce it, and check whether the answers are useful. This guide explains what each algorithm does and when it might be useful.

Start with one familiar table

Imagine a small collection of houses. Each row describes one house. The table is the same throughout this guide; only the question changes.

When making a prediction, we give the model information that is already available, such as a house’s number of bedrooms, area, and age. We keep the answer we want to estimate—its sale price—separate. Otherwise, we would be showing the model the answer in advance.

The first question: what kind of answer do we need?

Before asking “Which algorithm?”, ask “What answer should come out?” That one question narrows the search far more usefully than starting with a favourite model.

Known answer: number

Regression

Use known examples to estimate a numerical value, such as a sale price.

Memory hook: “What number is likely?”
Known answer: category

Classification

Use known examples to choose between named possibilities, such as yes/no.

Memory hook: “Which category is likely?”
No answer supplied

Clustering

Group similar examples when nobody has supplied the group names in advance.

Memory hook: “Which belong together?”

The algorithm family map

These are the core families from the LMS section. The short purpose sits directly under each name so you can see the set before we study the members in detail.

Regression

Linear regression

Estimate a number by finding a useful straight-line relationship between clues and an answer.

Classification

Logistic regression

Estimate a probability, then turn it into a category such as “flat” or “house”.

Classification or regression

Ask a sequence of simple questions until an example reaches a result.

Many trees

Random forest / bagging

Ask many trees separately and combine their answers for a steadier result.

Many trees

Boosting

Build trees one after another, with each new tree paying attention to earlier mistakes.

Unsupervised learning

K-Means

Choose a number of groups and move their centres until nearby examples settle together.

Important boundary. This is a starter family, not every algorithm in machine learning. Neural networks, convolutional neural networks, anomaly detection, text models, and time-series models are signposted later as companion topics rather than squeezed into these explanations.

Predicting a number: linear regression

Suppose we want to estimate the sale price of a new house. Linear regression looks at old examples, finds the most useful straight-line pattern in them, and uses that line to estimate a new number.

“Fitting a line” is just a compact way of saying: try to place one line so that the total gap between the line and the old examples is as small as possible. Each gap is an error. The model learns working numbers that control the line; those numbers are called coefficients.

Plain picture: house details → a line through old examples → estimated sale price

With one clue, such as area, this is single linear regression. With several clues, such as area, bedrooms, and age, it is multiple linear regression. The idea stays the same: estimate a number from several clues.

Good starting point when…

A roughly straight relationship is plausible, the data is tabular, and you value a model that is relatively easy to inspect.

Watch out for…

A curved or complicated pattern, extreme outliers, or a claim that a coefficient proves causation. A line describes an association in the data; it does not automatically explain why the world behaves that way.

Choosing a category: logistic regression

Now change the question. Instead of asking “What price is likely?”, ask “Is this property a flat or a house?” The answer has two classes: flat and house.

Logistic regression first produces a number between 0 and 1 that we can read as a chance. A rule called a threshold then turns that chance into a final class. A threshold of 0.5 is a possible starting point, not a sacred law.

If a false alarm is costly—for example, sending a legitimate email to spam—you may use a stricter threshold. If missing a genuinely urgent request is more costly, you may choose a rule that catches more possible positives.

Plain-English translation of “logistic”. It names the S-shaped function used to turn a model’s score into a probability between 0 and 1. The important beginner idea is the two-step route: chance first, category second.

Asking questions with trees

A decision tree behaves like a flowchart. It asks a question, follows the answer down a branch, asks another question, and eventually reaches a prediction. For the house example, a simple tree might ask whether the area is large and whether the property has several bedrooms.

Overfitting in everyday language

A tree can keep asking more and more specific questions until it memorises old houses. It may look brilliant on the examples it saw and then stumble on a new property. Limiting depth or comparing on unseen data helps check whether it has learned a pattern rather than a list of exceptions.

When trees become a team

One tree is easy to picture, but one tree can be unstable. Ensemble methods combine several trees. The next panels show the two important routes: many separate opinions (bagging) and a chain of corrections (boosting).

Many trees: bagging, random forests, and boosting

Ensemble simply means a group of models used together. The difference is how the group is built and how the models learn from one another.

Random forest in plain English

Build many trees from slightly different samples of rows and available features, then combine their answers. The randomness helps stop one historical quirk from controlling the whole result.

Boosting in plain English

Build a small tree, look at its mistakes, build the next tree to pay more attention to those mistakes, and repeat. It can give strong results, but running too many rounds can make it learn noise.

Finding groups: K-Means

If nobody has supplied a target column, we cannot train against a known answer in the usual supervised way. If the useful question is “Which examples resemble one another?”, clustering becomes a candidate. K-Means is one of the simplest ways to demonstrate the idea.

  1. Choose K, the number of groups to try.
  2. Place one temporary centre in each group.
  3. Give each example its nearest centre.
  4. Move each centre towards the examples assigned to it, then repeat.
  5. Stop when the assignments and centres settle rather than continuing to move meaningfully.

Strengths

It is comparatively simple and can be quick on large datasets.

Limits

You must choose K; starting centres can affect the result; outliers can pull centres; and the method works best when groups have a shape its distance rule can represent.

Choosing and comparing algorithms

The LMS describes a useful first map, but the word suitable does not mean “automatically best”. Two candidates can both be sensible and still differ in accuracy, speed, interpretability, sensitivity to scaling, and the kinds of mistakes they make.

From data to a trustworthy result

“Fit a model” is only one part of the work. A reliable process keeps preparation, learning, evaluation, and prediction connected.

What “pipeline” means

It is not storage, a user interface, or physical infrastructure. It is a repeatable chain of preparation and modelling steps that can be applied in the same order to training data and new data.

What leakage means

Leakage happens when information that would not be available at prediction time slips into training or evaluation. The score looks wonderful, but the model performs worse in real life. Split first, learn preparation from training data, and keep the test set untouched until the comparison is ready.

How do we know whether it helped?

A model is not “good” in the abstract. Its result has to be measured against a meaningful baseline and a metric that matches the decision.

Regression: MAEAverage size of the error, in the target’s units. Easy to explain: “about 6 minutes out.”
Regression: RMSELike an error average, but large misses count more heavily.
Regression: R²How much variation the model explains compared with a simple baseline. It is not a percentage of accuracy.
Classification: accuracyHow often the model is right overall. It can mislead when one class is much more common.
Classification: precisionWhen the model says “positive”, how often is that correct?
Classification: recallOf all the real positive cases, how many did the model find? Also called sensitivity.

A confusion matrix keeps the types of mistake visible instead of hiding them inside one score.

Clustering is different

There is no supplied “correct group” in ordinary unsupervised clustering. Measures such as silhouette score can help, but a person still has to inspect whether the groups make sense for the problem.

Three traps to recognise

These are not just vocabulary words. They describe different symptoms, so the first repair is different in each case.

What you noticeWhat may have happenedFirst sensible response
Training score is high, new-data score is lowOverfitting: the model learned old detail or noise too closely.Try a simpler or more limited model, improve the examples, or use a suitable regularisation approach.
Training score and new-data score are both poorUnderfitting: the model is too simple to capture the useful pattern.Check the features and task definition, then compare a more suitable candidate.
Test score looks suspiciously perfectData leakage: information from the future or test set slipped into model building.Re-check the split and make sure preparation learns from training data only.
Baseline first. A baseline is a simple reference result—perhaps always predicting the most common class or the average number. A complicated model earns its place only when it improves the real outcome enough to justify its extra cost and complexity.

Finding quick wins

The third LMS lesson moves from algorithms to practical opportunities. A quick win is a small, safe trial that solves a repeated problem and has a clear way to measure whether it helped.

Faster first replies

Help-desk chatbot

Handle routine questions such as password resets immediately, then give unusual or sensitive cases to a person. Natural-language processing means working with ordinary human language.

Less searching

Document recommender

Suggest policies, templates, or technical documents that people in a similar role often need. Real systems usually find a shortlist, then put it in a useful order. Permissions still apply.

Find the meaning

Semantic search

Search for the meaning of a question, not only its exact words, across emails, presentations, and documents that are not tidy database rows.

Start from evidence

Existing reports

Traditional reports may reveal a repeated decision with a useful target to predict. The algorithm comes after the problem and the test plan.

Quick-win checklist. Is the task repeated? Is the data available and permitted? Is the risk low enough for a pilot? Can we define success? Can a person review uncertainty or take over? Can the existing service continue if the trial fails?

Beyond this starter set

These are companion signposts, not full lessons. They belong here because algorithm choice also depends on the kind of input.

Images

Convolutional neural networks

Neural networks designed to learn useful local patterns in images. With limited task data, transfer learning can reuse features learned from a much larger image collection.

Unusual cases

Anomaly detection

Look for observations that differ sharply from what is normal, such as a faulty sensor reading or unusual transaction.

Other shapes

Text and time series

Text and time-ordered measurements carry structure of their own. The task type still matters, but the preparation and candidate families may change.

Recall and transfer

Try to answer before opening the explanations.

  1. We want to estimate the sale price of a new house. Which task family fits?
  2. We want to decide whether a property is a flat or a house. Which task family fits?
  3. No property-type labels are supplied, but we want to discover natural groups of similar houses. Which task family fits?
  4. Why does a logistic model need a threshold after it has produced a probability?
  5. In one sentence, how is bagging different from boosting?
  6. What can go wrong if you scale or select features using the test data before evaluation?
  7. A model has 98% accuracy because 98% of cases are “no”. What should you inspect next?
  8. Give one safety question you would ask before turning a help-desk chatbot into a quick win.
Reveal answers and reasoning
  1. Regression — the target is a numerical amount.
  2. Classification — the target is a named class, such as yes/no.
  3. Clustering — the groups are discovered without supplied labels.
  4. The probability is not yet the final class. The threshold is the rule that turns “how likely?” into “yes” or “no”.
  5. Bagging asks many separately trained trees and combines their answers; boosting builds trees in sequence, with later trees responding to earlier mistakes.
  6. The evaluation can leak information from the test set and look better than real-world performance. Split first and learn preparation from training data only.
  7. Inspect the confusion matrix, precision, recall, and the actual cost of each error; accuracy alone is hiding the class imbalance.
  8. For example: “Can a person review uncertain or sensitive answers and take over?” Other sensible answers include permissions, privacy, a measurable baseline, and a safe fallback.
